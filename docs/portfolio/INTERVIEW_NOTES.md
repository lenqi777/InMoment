# InMoment 求职介绍与面试准备

## 简历项目介绍

**InMoment｜Windows 灵感记录工具｜个人产品项目**

- 从自己在阅读和资料收集中的记录习惯出发，设计“先记录、后整理、按描述找回”的使用流程，推进 Windows 桌面应用。
- 设计本地转写、语义检索与云端总结、归类的分工，明确发送范围、截图授权和分类确认流程。
- 根据多轮试用调整分栏阅读、就地操作、多选管理和批量分类，将逐条推荐组名改为整批比较摘要、形成共同主题。
- 负责需求、交互、AI 方案和验收，借助 AI 编程工具完成实现与测试；整理版本记录、演示和评测计划。

## 两分钟项目介绍

> 我做了一个叫 InMoment 的 Windows 灵感记录工具。起因是我自己在浏览资料时，经常会想到一些东西。收藏链接很容易，但过几天再看，就忘了当时为什么觉得它有用；马上切到笔记软件打字、分类，又会打断思路。
>
> 所以我想先把记录变得顺手一点。长按右键就能开始说，松开暂停，之后可以继续录。声音会和当时的窗口截图一起保存，没有选组就先进入未分类。回顾时再看转写、听原声，或者让 AI 帮忙总结和分组。
>
> 我觉得最有代表性的一次调整是分类。开始时，我让 AI 优先使用已有组，后来发现太宽泛；允许新建组以后，又容易变成一条记录建一个组。所以现在先总结每条记录，再把一批摘要放在一起比较，找共同主题。整理结果按组展示，我可以取消或修改建议，最后再确认应用。
>
> 找回方面，我加入了描述搜索。比如只记得“上个月想过一个做菜的点子”，可以按意思和时间查。本地先找候选，云端再排序，减少每次需要发送的内容。灵感云则提供另一种回顾方式，让相关想法连在一起。
>
> 这个项目里，我负责需求、流程、交互和验收，通过 AI 编程工具完成实现与测试。目前已经接入 AI 服务，下一步想用固定样本检查摘要、分类和搜索，再找有类似习惯的人试用，看看记录和找回到底能不能更顺手。

## 值得展开讲的三个故事

### 1. 为什么把分类放到记录之后

一开始需要回答的问题是：记录工具应该收集更多信息，还是让人尽快把想法说出来？

我的选择是先保留想法，分类、标题和整理放到之后。未分类有一个固定入口，用户可以先不做决定；AI 总结、手动分组和批量整理再承担后续工作。

这个选择也意味着需要把回顾做得方便。否则记录虽然容易，内容会一直堆在未分类里。我因此把记录和找回放在同一条流程里考虑。

### 2. 为什么列表最后只留标题

早期列表同时放了日期、状态和概述，看起来信息很全，但窄栏里读起来费劲。记录增加以后，还出现了标题被挤掉的问题。

我重新分配了界面空间：左侧小图标、分组栏和记录列表合起来占较少位置，详情留出主要阅读空间；分组主页用卡片，打开记录后用一行标题列表。列表操作也移到左滑或卡片菜单里，减少常驻按钮。

这次调整后，我用多条记录、多个分组和不同窗口尺寸检查实际显示。对我来说，这是从“页面能打开”到“内容多了以后还能用”的一次变化。

### 3. 为什么把逐条分类改成整批分类

逐条推荐组名的结果很容易碎片化，因为模型每次只看到一条内容。我希望得到的是一套方便浏览的共同主题。

现在先生成摘要，再集中比较本批内容；已有名称合适就复用，有共同新主题就推荐新组，孤立内容可以先不归类。应用层也限制组数，并要求多记录批次的新组至少有两条，减少一条一个组的情况。

接下来会把同一批样本放进两种方案，比较分组颗粒度和人工调整量，再决定这些约束是否合适。

## 常见追问

| 问题 | 我的回答思路 |
| --- | --- |
| 需求怎么来的？ | 从自己的桌面阅读和资料收集习惯开始，先做可运行版本，再用真实任务验证其他人是否也有同样的需要 |
| 和普通笔记工具有什么区别？ | 我把重点放在“当时为什么想到它”：声音保留表达，截图保留情境，之后再整理和找回 |
| 你具体负责什么？ | 需求、流程、界面交互、AI 功能取舍和验收；实现与测试借助 AI 编程工具 |
| 为什么本地和云端一起用？ | 原声留在本地，索引可以复用；云端处理总结和排序，同时控制发送内容和费用 |
| 为什么不把所有记录都发给模型？ | 先在本地缩小范围，避免每次重复发送整库；后续重点检查本地候选有没有漏掉目标内容 |
| 怎么判断摘要是否可靠？ | 保留原文、截图和原声，检查引用；评测时对照关键意思，看遗漏、误解和用户修改量 |
| 分类效果怎么评价？ | 先看哪些内容适合放在一起，再看组名是否好理解、好找回，并记录人工修改了多少 |
| 怎么排下一步优先级？ | 先测摘要、分类和搜索能不能完成实际任务，再决定功能扩展和更多软件适配 |

## 演示准备

演示可以沿着“打开一组 → 阅读一条记录 → 查看摘要和原文 → 手动或批量整理 → 搜索找回”的顺序展开，挑两个关键取舍穿插说明即可。

当前演示使用示例记录，摘要和分组提前准备。若面试时现场演示云端功能，提前确认网络、密钥和发送内容。

版本历史来自已有代码、构建和开发记录的回顾整理。面试时选一两次有代表性的改动讲清楚，会比逐个介绍版本号更有说服力。

目前尚未开展正式外部用户研究、真实搜索召回评测和记录流程的节省时长统计。
