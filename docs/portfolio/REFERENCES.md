# 写作和演示参考

这次整理介绍材料时，我参考了几个同类项目和演示工具，主要看它们怎样介绍用途、安排演示顺序。

## 项目介绍

- [Memos](https://github.com/usememos/memos)：开头就讲随手记录和以后找回，功能也围绕这些动作展开。我把 README 的场景和使用流程放在了前面。
- [Cap](https://github.com/CapSoftware/Cap)：产品用途、使用方式和开发说明各有入口。InMoment 也将产品案例、使用指南和开发指南分开，首页只保留主要内容。
- [Karakeep](https://github.com/karakeep-app/karakeep)：从收藏和整理内容的实际需求介绍产品。我重新写了自己为什么开始做 InMoment，以及使用过程中遇到的问题。

## 视频与动效

- [Screen Studio](https://screen.studio/)：跟随操作放大、平滑光标和留白，让人容易看见当前在做什么。演示沿一条实际操作路径展开，在关键动作处放大。
- [Tella 案例库](https://www.tella.com/examples)：参考产品演示的节奏，先交代场景，再展示一段完整流程。
- [Jitter 官方动效模板](https://jitter.video/templates/)：参考界面片段的转场方式，以及用手势和短标注引导视线的结构；鼠标手势、按钮放大和转场都自行制作，没有复制模板素材。
- [Remotion 官方动画规范](https://github.com/remotion-dev/skills/blob/main/skills/remotion-markup/SKILL.md)：用明确的帧或时间计算动画，方便随时抽帧检查。
- [programatic-demo](https://github.com/ashrafchowdury/programatic-demo)：参考操作与镜头分开的设计，阅读和输入时保持稳定构图。
- [saas-product-demo-video](https://github.com/noamdorr/saas-product-demo-video)：参考将画面、短句、动作和声音写在同一张分镜表里的方式。
- [Microsoft 写作风格](https://learn.microsoft.com/en-us/style-guide/brand-voice-above-all-simple-human)：用短句、具体动作和日常说法，把话说清楚。

项目经历和屏幕解释词都按 InMoment 的内容重写。新版视频以我提供的参考片确定配色和节奏，公开版去除参考片的音乐与音效，界面画面来自自己的程序。没有使用上述开源项目的视频、音轨或模板素材。[完整分镜与提示词](VIDEO_PROMPT.md)单独保存，便于之后更新。

- [Manoj 的产品作品集](https://github.com/Manojsabavat/product-management-portfolio)：README 介绍每份 PRD 的主题，全文放在独立目录。
