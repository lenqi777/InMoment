# InMoment 的 AI 方案与评测计划

我把 AI 用在三个地方：把声音变成文字、帮助整理表达、根据意思找回记录。保存、删除、重命名和分组管理继续用普通程序逻辑处理。

云端总结、批量归类和搜索排序已接入 DeepSeek。这份说明对应 v0.10.0，主要记录我为什么这样拆分功能，以及接下来准备怎样评估效果。

## 功能分工

| 功能 | 当前方案 | 处理内容 |
| --- | --- | --- |
| 语音转写 | 本地 whisper.cpp，多语言 base 模型 | 将保存的分段音频转成文字，保留原声和修改入口 |
| 单条总结 | 云端 DeepSeek | 根据转写、补充说明和来源线索生成标题、摘要与分组建议；授权后可附保存的截图 |
| 批量整理 | 逐条总结，再统一归类 | 比较本批摘要，提出共享分组，预览确认后应用 |
| 描述搜索 | 本地 E5 语义召回、关键词检索与云端排序 | 从描述和时间范围中寻找相关记录，附匹配理由与原话 |
| 灵感云 | 本地向量、互为近邻图与社区划分 | 将相似记录连成可浏览的灵感团 |

项目使用现成模型，没有训练或微调模型。程序与测试通过 AI 编程工具辅助完成。

## 总结：保留表达，再做压缩

用户的语音文本是主要内容，截图用于补充情境。比如一段话提到“这张图的留白很舒服”，画面可以帮助理解“这张图”指的是什么，但摘要仍然围绕用户自己的表达展开。

总结返回标题、摘要、原话依据、待确认内容和分组建议。程序检查输出结构及引文，详情里也能切回原文、查看截图和播放原声。这样的设计方便发现误解，并在修改原文后重新整理。

只有用户启用并授权云端功能后才发送请求。截图授权单独设置，原始音频留在本地。

实现入口：[总结提示与结果校验](../../src/core/deepseek.cjs)。

## 批量整理：先看整批，再决定怎么分

逐条生成组名时，模型只能看到眼前的一条内容，容易得到一批精确却零碎的标签。我希望最后得到的是方便浏览的共同主题，所以把批量流程改成了两步。

1. 固定当前页面显示的记录，为每条记录生成摘要。
2. 将成功生成的标题和摘要放在一起，统一设计分组。

统一归类可以复用已有名称，也可以推荐新组。提示中要求合并同义主题，不按录音方式、来源软件或“灵感”字样分类。明显孤立的内容可以保留未分类，已有合适分组也可以只接收一条新记录。

目前设置了几项规模约束：

- 一次最多整理 100 条，只处理点击时显示的范围。
- 分组数量上限取记录数平方根向上取整，最多 8 组；模型可以少于这个数量。
- 多条记录的批次中新建组至少包含两条，减少“一条一组”。
- 最多提供 50 个已有组候选，统一归类输入最多 96,000 字节。

这些是当前控制分类颗粒度和请求规模的方法。后续会结合实际分类结果，调整组数和最小成员数。

结果先按组预览，用户可以取消或修改每条建议，再确认采用。记录版本也会一起检查，避免整理期间的旧结果覆盖后来的编辑。

实现入口：[批量任务编排](../../src/main/batch-organizer.cjs)、[归类提示与校验](../../src/core/deepseek.cjs)。

## 描述搜索：本地找候选，云端再排序

“想找之前那个做菜的点子”不一定能匹配原文里的某个关键词。为此，我加入了本地语义向量，并和关键词检索一起使用。

大致流程是：

**描述与时间范围 → 本地语义和关键词候选 → 云端排序 → 相关记录、匹配理由和原话。**

本地语义索引会随内容修改而更新，删除记录时清理对应索引。搜索最多将 20 条候选交给云端，最终最多展示 8 条；一次搜索最多包含两次请求。这样能控制上传内容和费用，也让每次搜索复用之前建立的索引。

需要重点评估的是召回：如果目标记录没有进入这 20 条候选，云端排序也无法补回来。另外，长文本分片有数量限制，本地向量当前采用遍历检索，大量记录下的速度和资源占用需要进一步测试。

实现入口：[语义索引](../../src/main/semantic-service.cjs)、[描述搜索](../../src/main/library-ai.cjs)。

## 灵感云：给没有明确目标的回顾留一个入口

描述搜索适合“我想找什么”，灵感云适合“我想看看之前有哪些想法”。

每条灵感对应一个节点。程序计算向量相似度，只保留达到阈值、并且互相进入近邻列表的连接，再通过社区划分形成相似团。孤立节点继续单独保留。界面支持平移、缩放、聚焦关联节点和打开记录。

这些连接表示内容相似，不改变用户手动设置的分组。当前默认相似度阈值为 0.84、近邻数量为 5，后续会结合样本检查误连和漏连。

实现入口：[相似图与社区划分](../../src/core/semantic-graph.cjs)。

## 数据、费用和中断处理

| 关注点 | 当前处理 |
| --- | --- |
| 密钥 | 通过 Windows DPAPI 保存，用户在本机设置自己的密钥 |
| 发送范围 | 单条总结发送当前记录资料；统一归类发送本批标题、摘要与组名；搜索发送有限候选片段 |
| 截图 | 独立授权后参与总结，搜索不附截图 |
| 请求规模 | 批量最多本批条数加一次请求，配合文字、图片和输入长度上限 |
| 费用 | 请求前限制规模，请求后记录服务返回的 usage；中途取消时，已经发送的请求仍可能计费 |
| 取消和编辑 | 停止后续请求，检查记录版本，保留原始资料和已完成摘要 |
| 分类应用 | 先展示建议，确认后才创建分组或调整归属 |

本地保存依赖设备和系统账户权限。DPAPI 保护的是密钥，记录库整体没有加密。更多说明见 [隐私说明](../../PRIVACY.md)。

## 现有验证和后续评测

v0.10 的验证记录为 378 项测试通过、1 项桌面输入测试默认跳过。AI 流程使用模拟响应，覆盖授权、发送范围、预算、结构校验、内容版本、取消和部分失败等情况；界面检查使用合成记录与向量。

接下来准备使用固定样本分别检查内容质量、任务体验和资源成本。样本先采用合成或获得授权的非敏感材料，真实模型和 API 评测另行确认。

| 对象 | 怎么测 | 主要看什么 |
| --- | --- | --- |
| 捕捉交互 | 在浏览器、阅读器中完成长按、暂停、续录、丢弃 | 任务完成、误触、右键干扰、停止延迟 |
| 中文转写 | 对照人工原文，加入专有名词、噪声和停顿 | 字错率，以及人名、数字、否定词等关键错误 |
| 摘要 | 先标出原文的关键意思，再对照摘要 | 原意保留、重点遗漏、额外添加内容、修改量 |
| 分类 | 同批加入共同主题、同义表达、跨主题和孤立项，对比逐条与整批方案 | 拆得太细、合得太宽、组名易懂程度、人工调整量 |
| 描述搜索 | 为模糊描述标注相关记录，覆盖带时间、不带时间、同义词和无结果的查询 | 候选 Recall@20、最终 Recall@8 与 Precision@8、找回耗时 |
| 灵感云 | 抽样检查相连和未相连的记录对 | 有用连接、误连和漏连 |
| 成本与资源 | 固定设备、记录规模、模型和网络条件 | 索引时间、内存、请求耗时、实际 token 与每次成功任务费用 |

分类的判断会先看内容是否适合放在一起，再看名称是否方便找回。评测记录保留样本、提示词和模型版本，便于比较不同方案。

目前还没有完成真实 AI 质量、搜索召回和任务节省时长的系统评测。
